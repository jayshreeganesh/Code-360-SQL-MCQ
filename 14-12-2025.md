## 3. Differential Backup Advantage

**Problem statement**
What is a key advantage of a differential backup over an incremental backup?

**Options**

- It requires less storage space than incremental backups.
- **It simplifies recovery by requiring only the full backup and the latest differential backup.** ✅
- It captures changes made since the last incremental backup.
- It acts as a standalone backup that does not rely on other backups.

**Solution description**
Differential backups copy all changes made since the last full backup. For recovery, only the full backup and the most recent differential backup are needed.

## 4. Data Export

**Problem statement**
Choose the correct query for exporting data in SQL from the following.

**Options**

1. `SELECT * FROM UFC WHERE id = 1 INTO OUTFILE 'C:/tmp/conner_vs_khabib2.csv';`
2. `SELECT * FROM UFC WHERE id = 1 INTO OUTFILE 'C:/tmp/conner_vs_khabib2.csv' FIELDS ENCLOSED BY '"' TERMINATED BY ';' ESCAPED BY '"' LINES TERMINATED BY '\n';` ✅
3. `SELECT * FROM UFC WHERE id = 1 INTO OUTFILE 'C:/tmp/conner_vs_khabib2.csv' FIELDS TERMINATED BY ',' ENCLOSED BY '"' LINES TERMINATED BY '\n' IGNORE 1 ROWS;`
4. `SELECT * FROM UFC WHERE id = 1 LOAD DATA OUTFILE 'C:/tmp/conner_vs_khabib2.csv' FIELDS TERMINATED BY ',' ENCLOSED BY '"' LINES TERMINATED BY '\n' IGNORE 1 ROWS;`

**Solution description**
To export data into a CSV file, use `SELECT column_name(s) FROM T_name WHERE id = 1 INTO OUTFILE 'C:/tmp/xyz_exported.csv' FIELDS ENCLOSED BY '"' TERMINATED BY ';' ESCAPED BY '"' LINES TERMINATED BY '\n';`. The clauses handle how fields and lines are formatted in the file.

## 5. Key Update

**Problem statement**
There are two tables, Employee and Payment. The id of the Employee table acts as a foreign key for the Payment table. It is realized that the current id (103) of an employee should be replaced with the correct id 100. Which of the following statements is correct for this scenario?

**Options**

- We cannot update the id of the employee.
- We should update the correct value of id in the employee table only.
- **We should make sure that if we are updating the correct value of id in the Employee table, it should also get updated in another table referencing it (Payment table) so that the data remains consistent.** ✅
- None of the above is correct.

**Solution description**
Update the current_id in the Employee table and also update the referencing foreign key in the Payment table so that referential integrity and data consistency are maintained.
