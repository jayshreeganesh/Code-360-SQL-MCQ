## Question 3: Multi-level Indexing

**Problem statement**

> Which of the following will be considered as multi-level indexing in Database?

**Options**

- Clustering indexing
- **Secondary indexing** ✅
- Primary indexing
- All of them

**Solution description**

> Secondary index is taken into consideration when the size of datafile increases, i.e., when the size of the table increases, sparse indexing starts to slow down.
> To overcome this, another level of indexing is introduced that is known as secondary indexing. In this, a huge chunk of columns is selected initially and put at the first level of indexing which is known as primary level indexing.
> The data of primary level indexing is stored in primary memory. After this, each chunk is divided into smaller ranges. This is known as the second level of indexing; this is stored in the secondary memory along with the actual data file. Secondary indexing is also known as multilevel indexing.

## Question 4: Replace vs Update

**Problem statement**

> Choose the correct statement regarding REPLACE and UPDATE in database:

**Options**

- If the row which we want to replace is not present, REPLACE will not do anything but UPDATE will add a new row.
- UPDATE deletes the old data and then adds new data while REPLACE always makes changes in current data.
- **If the row is not present, REPLACE will add a new row and UPDATE will not do anything.** ✅
- REPLACE is faster than UPDATE because it always adds new data instead of making changes in existing one.

**Solution description**

> REPLACE adds new rows if they do not exist and updates old rows in case they already existed. UPDATE makes changes in existing rows.
> Hence, option A is not correct as REPLACE will insert the row and UPDATE will not do anything if row is not present.
> Option B is not correct as UPDATE makes changes in existing data while REPLACE makes changes according to row presence or absence.
> Option D is not correct as UPDATE is faster because REPLACE has to add new data while UPDATE has to make changes in current one.

## Question 5: Data Fragmentation

**Problem statement**

> Some of the columns of a relation are at different sites in which of the following techniques in SQL?

**Options**

- Data Replication
- Horizontal Partitioning
- **Vertical Partitioning** ✅
- Horizontal and Vertical Partitioning

**Solution description**

> To partition the data there are two techniques:
> 1. Vertical Partitioning: In this, the given data is partitioned vertically i.e. column-wise. For example, consider a table `students` with attributes student_id, name, course_id, address. This data can be stored by distributing it among servers where student_id is stored on one server, name on another, course_id on another and address on a fourth.
> 2. Horizontal Partitioning: In this, the given data is partitioned horizontally i.e. row-wise, so chunks of data of certain size are stored at different servers.
