## **Question 2: Indirect FD**

**Problem Statement:**
A \_\_\_\_\_\_\_\_\_\_ is an indirect functional dependency, one in which $X \rightarrow Z$ only by virtue of $X \rightarrow Y$ and $Y \rightarrow Z$ in database.

**Options:**
*   [ ] Multivalued Dependencies
*   [ ] Join Dependency
*   [ ] Trivial Functional Dependency
*   [x] **Transitive Dependency**

**Solution Description:**
Third Normal Form deals with something called 'transitive' dependencies. This means if we have a primary key A and a non-key domain B and C where C is more dependent on B than A and B is directly dependent on A, then C can be considered transitively dependent on A.

RDBMS consists of a collection of?

**Options:**
*   [x] **Tables**

*   [ ] Keys

## **Question 4: Key Update**

**Problem Statement:**
There are two tables: `Employee` and `Payment`. The `id` of the `Employee` table acts as a foreign key for the `Payment` table. Refer to the tables given below:

**Employee Table:**
| id | Name | gender | hire_date |
| :--- | :--- | :--- | :--- |
| 101 | Bryan | M | 2015-08-26 |
| 102 | Joseph | M | 2014-10-21 |
| 103 | Mike | M | 2017-10-28 |
| 104 | Daren | M | 2006-11-01 |
| 105 | Marie | F | 2018-10-12 |

**Payment Table:**
| payment_id | id | amount | payment_date |
| :--- | :--- | :--- | :--- |
| 301 | 101 | 1200 | 2015-09-15 |
| 302 | 101 | 1200 | 2015-09-30 |
| 303 | 101 | 1500 | 2015-10-15 |
| 304 | 101 | 1500 | 2015-10-30 |
| 305 | 103 | 1800 | 2015-09-15 |
| 306 | 102 | 1800 | 2015-09-30 |

It has been realized that the current `id` (103) of an employee should be replaced with his correct `id` which is 100. Which of the following statements is correct for this scenario?

**Options:**
*   [ ] We cannot update the id of the employee
*   [ ] We should update the correct value of id in the employee table only
*   [x] **We should make sure that if we are updating the correct value of id in the Employee table, it should also get updated in another table referencing it (Payment table) so that the data remains consistent.**
*   [ ] None of the above is correct

**Solution Description:**
We can update the current `id` of employees from 103 to 100 because the current `id` value 100 is not present in the database. current `id` is a primary key so its value should be unique. If `current_id = 100` existed before, then it is not possible to update but this is not the issue here. We should update the correct value of `current_id` in the employee table as well as the payment table. We should make sure that if we are updating the correct value of `id` in the Employee table, it should also get updated in the Payment table so that the data remains consistent.
