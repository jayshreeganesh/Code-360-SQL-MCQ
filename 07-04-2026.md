## 1. SQL INNER JOIN
**Problem Statement:** What does an INNER JOIN return in SQL?

* **Options:**
    * All records from both tables
    * **Only matching records** (Correct)
    * Only unmatched records
    * First table records
* **Solution Description:** INNER JOIN returns rows when there is a match in both tables.

## 2. 3NF (Third Normal Form)
**Problem Statement:** In DBMS, third normal form is inadequate in situations where the relation:

* **Options:**
    * has multiple candidate keys
    * has candidate keys that are composite
    * has overlapped candidate keys
    * **None of the above** (Correct)
* **Solution Description:** Third normal form is inadequate in situations where the relation is none of the above relation. *(Note: This usually refers to the need for BCNF when overlapping candidate keys exist).*

## 3. Data Modelling
**Problem Statement:** Data modelling helps in achieving abstraction in DBMS.

* **Options:**
    * **True** (Correct)
    * False
* **Solution Description:** Abstraction means showing only what is required and hiding the extra information. This is achieved through the three kind of data modelling: Conceptual, Representational and Physical data models.

## 4. Handling Large Indexes
**Problem Statement:** What happens when the first-level index in a database becomes too large?

* **Options:**
    * The system stops using indexes for searches.
    * **A second-level index is created to point to entries in the first-level index.** (Correct)
    * The first-level index is divided into smaller tables.
    * The database automatically optimizes queries without using the index.
* **Solution Description:** When the first-level index becomes too large to fit in memory, a second-level index is created. This index points to entries in the first-level index, enabling efficient management of large datasets.

## 5. Schema Mapping
**Problem Statement:** Which of the following relational database schemas is a correct representation for the following ER diagram?
*(Diagram shows a **Student** entity with attributes: Name, Phone No., Course, Roll No., and a composite/multivalued **Address** containing House No. and City).*

* **Options:**
    * `Student(Name, Phone no., Course, Roll No., House no., City)`
    * **`Student(Name, Phone no., Course, Roll No.) Address(House no., City, Roll no.)`** (Correct)
    * `Student(Name, Phone no., Course, Roll No., Address, House no., City, Roll no.)`
    * All of the above
* **Solution Description:** In the ER diagram, the rectangle represents entity sets, while the ellipse represents attributes. Double ellipses represent multi-valued attributes. To convert to a relational schema: 
    1. Every strong entity set becomes a relation.
    2. Attributes of the entity sets are attributes in the schema.
    3. For multi-valued attributes, we create a separate table and include the primary key of the parent entity as a foreign key. 
    In this case, Address is treated as multi-valued/complex, so a new relation 'Address' is created with House No., City, and Roll No. (Foreign Key) to connect to the 'Student' relation.
