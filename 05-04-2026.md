## 1. SQL ALTER Command (Purpose)
**Problem Statement:** What does the `ALTER` command do in SQL?

* [ ] Modifies data
* [x] **Modifies table structure**
* [ ] Deletes a table
* [ ] Joins tables

**Solution Description:**
The `ALTER` command is used to modify the structure of a table, such as adding a column.

## 2. Boyce-Codd Normal Form (BCNF)
**Problem Statement:** In DBMS, which one of the following statements about normal forms is **FALSE**?

* [ ] Lossless, dependency-preserving decomposition into 3 NF is always possible
* [ ] BCNF is stricter than 3 NF
* [x] **Lossless, dependency-preserving decomposition into BCNF is always possible**
* [ ] Any relation with two attributes is BCNF

**Solution Description:**
We say that the decomposition is a lossless decomposition if there is no loss of information by replacing $r(R)$ with two relation schemas $r_1(R_1)$ and $r_2(R_2)$.
*(Note: The statement marked correct is false because while BCNF decomposition is always lossless, it is not always dependency-preserving.)*

## 3. ALTER Command (Category)
**Problem Statement:** In SQL, `ALTER` command is a type of:

* [ ] Data Manipulation Language
* [x] **Data Definition Language**
* [ ] Data Control Language
* [ ] None of the above

**Solution Description:**
`ALTER` commands modify the structure of the table and hence is a kind of Data Definition Language (DDL).

## 4. Indirect Functional Dependency
**Problem Statement:** A __________ is an indirect functional dependency, one in which $X \rightarrow Z$ only by virtue of $X \rightarrow Y$ and $Y \rightarrow Z$ in database.

* [ ] Multivalued Dependencies
* [ ] Join Dependency
* [ ] Trivial Functional Dependency
* [x] **Transitive Dependency**

**Solution Description:**
Third Normal Form deals with something called 'transitive' dependencies. This means if we have a primary key A and a non-key domain B and C where C is more dependent on B than A and B is directly dependent on A, then C can be considered transitively dependent on A.

## 5. Dirty Read Example
**Problem Statement:** Which of the following is an example of a dirty read in database transactions?

* [x] **A transaction reads data that another transaction has not yet committed.**
* [ ] A transaction updates the same record as another transaction, overwriting changes.
* [ ] A transaction retrieves inconsistent results due to other transactions inserting or deleting rows.
* [ ] A transaction locks a table, preventing others from accessing it.

**Solution Description:**
A dirty read occurs when one transaction reads uncommitted changes made by another transaction. If the changes are later rolled back, the data read becomes invalid.
